Lesson 4 · 13 min

Everything with tongs: each agent's model and the tool that comes in (or not)

Every week a new repository shows up promising everything. Handle it with tongs: before installing, ask your AI whether it fits your stack and what you gain. And don't use the same model for everything: each agent can have its own, among the best, the economical and the free.

Start the lesson

In this lesson you will

  1. 1Three model tiers: the best, the economical and the free
  2. 2Four questions before you install any tool
  3. 3Two opinions on a sensitive topic
  4. 4Why the plan takes longer than the execution

Goal: choose each agent's model by cost and task, and test any new tool against your stack before installing it.

01 · New tool: in or out?

Tap each step.

Click each block in the diagram to see what it does.

02 · The model for each agent

Three tiers. The names change every month; the criteria stay.

1. The best

Coding, finance and decisions involving money call for the strongest model your plan offers.

The cost of an error here is higher than the price difference.

2. Budget

Customer service, triage and summaries run many times a day. A cheaper, faster model can handle them.

Test with 20 real cases before switching.

3. Free

There are open, free models with huge context windows, good for prototyping and for tasks with no sensitive data.

Check the provider's data policy: free sometimes means your data trains the model.

4. Two opinions

For a financial plan, ask two agents running different models for the same analysis, with the same context, and compare.

Where they agree, you gain confidence; where they disagree, that's the question you need to ask.

03 · Templates to copy

Run the first one in the AI that already knows your project.

Prompt · does the tool fit?
Someone recommended this tool to me: <name and link>.
You know my stack (languages, services, what's already running).

Answer in up to 10 lines:
1. DOES IT FIT? What language and infrastructure does it run on, and does that work with my stack?
2. DO I ALREADY HAVE IT? What I already use that does the same thing or close to it.
3. WHAT DO I GAIN? One concrete task that would get better, with a number if possible.
4. RISK? Data access, maintenance, license, dependence on third parties.

Verdict: IN (<deadline> test on one task) or OUT (reason in 1 line).
